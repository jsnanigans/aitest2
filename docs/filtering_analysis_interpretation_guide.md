## Overview

The filtering analysis script evaluates the effectiveness of our weight measurement filtering system by comparing raw (unfiltered) data against filtered data. The system uses Kalman filtering and intelligent outlier detection to improve data quality while preserving clinical validity.

### What the Analysis Does

- **Compares** raw vs filtered weight measurements
- **Quantifies** improvements in data reliability
- **Assesses** clinical impact on weight loss outcomes
- **Generates** comprehensive visualizations and reports
- **Analyzes** quarterly business metrics (90+ day users)

#### Clinical Success Rates
Percentage achieving weight loss thresholds:

**How Success Rates Are Calculated:**

1. **Eligible Users**: Users with 90+ days in program (from employer CSV)
2. **Valid Data Users**: Users with both start weight and end weight available
3. **Success Calculation**: `users_achieving_threshold / users_with_valid_endpoint * 100`

**Example Calculation:**
- Eligible Users: 1000 users with 90+ days
- Valid Data (Raw): 750 users (75%) - missing data due to insufficient measurements
- 5% Success (Raw): 300 users achieved ≥5% loss → 300/750 = 40.0% success rate
- Valid Data (Filtered): 720 users (72%) - slightly fewer due to filtering
- 5% Success (Filtered): 305 users achieved ≥5% loss → 305/720 = 42.4% success rate

**Where Users Are "Lost":**
- **~25% Missing Data**: No valid start/end weight (insufficient measurements, gaps in data)
- **~3% Filtering Loss**: Users who lose too many measurements to calculate endpoint
- **Remaining ~72%**: Have valid weight loss calculations

**Thresholds:**
- **5% Weight Loss**: Clinically significant threshold
- **10% Weight Loss**: Substantial weight loss marker
- **15% Weight Loss**: Exceptional outcome marker
- **Delta**: Change in success rates due to filtering

**Important Notes:**
- Success rates are calculated only on users with valid data (not all eligible users)
- The denominator is `users_with_valid_endpoint`, not `eligible_users`
- Users without sufficient measurements are excluded from both numerator and denominator
- This explains why ~25% of users don't appear in success rate calculations

**Good Results:**
- Filtered success rates ≥ raw success rates
- Deltas should be small (<5%) to avoid over-optimistic reporting
- Valid data rates >70% indicate good data completeness

#### User Inclusion Impact

**Red Flags:**
- Large drops in valid users (>20%) may indicate over-filtering
- Baseline should have more valid users than endpoint

#### Statistical Power Improvements

**What is Statistical Power?**
Statistical power is the probability of detecting a true effect when it exists. Higher power means you're more likely to find real weight loss effects and less likely to miss them due to noise in the data.

**Variance Reduction**
- **Definition**: The decrease in variability of weight change measurements after filtering
- **Formula**: `(Raw_Variance - Filtered_Variance) / Raw_Variance × 100%`
- **Calculation Example**:
  ```
  Raw weight changes: [-2, +5, -8, +3, -4, -1, +7, -6] kg
  Raw variance: 25.5 kg²

  Filtered weight changes: [-2, -3, -4, -1, -3, -2] kg (outliers removed)
  Filtered variance: 1.2 kg²

  Variance Reduction: (25.5 - 1.2) / 25.5 = 95.3%
  ```
- **Why It Matters**:
  - Lower variance = tighter confidence intervals
  - More precise estimates of true weight change
  - Smaller sample sizes needed for statistical significance
  - Better ability to detect treatment effects

**Effect Size Improvement**
- **Definition**: The standardized difference between groups, measured in standard deviations
- **Formula**: `|Mean_Weight_Loss| / Pooled_Standard_Deviation`
- **Cohen's d Calculation**:
  ```
  Pooled_SD = √((Raw_Variance + Filtered_Variance) / 2)
  Effect_Size = |Filtered_Mean_Change| / Pooled_SD
  ```
- **Interpretation Scale**:
  - Small effect: 0.2 - 0.5
  - Medium effect: 0.5 - 0.8
  - Large effect: > 0.8
- **Example**:
  ```
  Filtered mean weight loss: -5.2 kg
  Pooled standard deviation: 3.8 kg
  Effect size: 5.2 / 3.8 = 1.37 (large effect)
  ```

**Practical Impact on Studies**:

1. **Sample Size Requirements**:
   - 10% variance reduction → ~5% smaller sample needed
   - 20% variance reduction → ~10% smaller sample needed
   - 30% variance reduction → ~15% smaller sample needed
   - 50% variance reduction → ~25% smaller sample needed

2. **Detection Capability**:
   - Effect size 0.2 → Need ~400 participants per group
   - Effect size 0.5 → Need ~65 participants per group
   - Effect size 0.8 → Need ~25 participants per group
   - Effect size 1.0 → Need ~15 participants per group

3. **Clinical Trial Benefits**:
   - **Faster enrollment**: Smaller required sample size
   - **Lower costs**: Fewer participants to recruit and monitor
   - **Earlier results**: Reach statistical significance sooner
   - **Better precision**: Narrower confidence intervals around estimates

**Good Values to See**:
- **Variance Reduction**: 15-40% (substantial improvement without over-filtering)
- **Effect Size**: > 0.5 (medium to large effect, easier to detect)
- **Combined Impact**: Both metrics improving together indicates genuine data quality enhancement

**Warning Signs**:
- **Variance Reduction > 60%**: Possible over-filtering, removing real variation
- **Effect Size < 0.2**: May struggle to detect real effects even with filtering
- **Negative variance reduction**: Filtered data is more variable (system problem)

**Real-World Clinical Trial Example**:

Consider a weight loss intervention study comparing treatment vs control:

*Without Filtering:*
- Mean difference: 2.5 kg between groups
- Standard deviation: 8 kg (high due to measurement noise)
- Effect size: 2.5/8 = 0.31 (small effect)
- Sample needed: ~165 participants per arm (330 total)
- Study duration: 18 months to enroll
- Study cost: $1.65M @ $5,000 per participant

*With Filtering (30% variance reduction):*
- Mean difference: 2.8 kg (clearer signal)
- Standard deviation: 5.6 kg (reduced noise)
- Effect size: 2.8/5.6 = 0.50 (medium effect)
- Sample needed: ~65 participants per arm (130 total)
- Study duration: 7 months to enroll
- Study cost: $650,000
- **Savings: $1M and 11 months**

This demonstrates why statistical power improvements are crucial for:
- Pharmaceutical companies running clinical trials
- Academic researchers with limited funding
- Digital health companies proving efficacy
- Healthcare systems evaluating interventions

## User Flow and Data Loss Analysis

### Understanding the "Missing" 25% of Users

The quarterly analysis reveals where users are excluded from success rate calculations:

#### Step-by-Step User Flow:

1. **All Users in Program**: Total users enrolled
2. **Eligible Users (90+ days)**: Users with sufficient program duration
3. **Users with Weight Data**: Users who appear in the weight measurement dataset
4. **Valid Start Weight**: Users with weight measurement near their program start date (±14 days)
5. **Valid End Weight**: Users with weight measurement after 90+ days in program
6. **Valid Weight Loss Calculation**: Users with both valid start and end weights

#### Common Reasons for User Exclusion:

**No Weight Data (5-10% loss):**
- User never submitted weight measurements
- User enrolled but never engaged with weight tracking
- Data integration issues

**Missing Start Weight (10-15% loss):**
- No measurements within 14 days of program start
- User started measuring weights weeks after enrollment
- Late adoption of weight tracking tools

**Missing End Weight (5-10% loss):**
- User stopped measuring weights before 90-day mark
- Data collection gaps or device issues
- User dropout or disengagement

**Insufficient Measurement Quality (2-5% loss):**
- Too few measurements to establish reliable endpoints
- Excessive outliers making data unreliable
- Measurement frequency too sparse for analysis

#### Filtering Impact on User Inclusion:

**Raw Data Path:**
- Eligible Users: 100%
- Valid Data: ~75% (25% excluded for missing measurements)
- Success Rate Denominator: Users with valid data only

**Filtered Data Path:**
- Eligible Users: 100%
- Valid Data: ~72% (additional 3% excluded due to filtering)
- Success Rate Denominator: Users with valid filtered data only

**Key Insight:** The "missing" 25% aren't hidden in the success rates - they're excluded from the analysis entirely due to insufficient data quality. This is standard practice in clinical studies where intent-to-treat analysis isn't always possible.

## Key Metrics Explained

### Removal Rate
**Definition:** Percentage of raw measurements filtered out
**Formula:** (Raw Count - Filtered Count) / Raw Count × 100%
**Good Range:** 10-30%
**Red Flags:** >50% (over-filtering) or <5% (under-filtering)

### Outlier Rate
**Definition:** Percentage of measurements identified as statistical outliers
**Methods:** IQR, MAD, and temporal consistency checks
**Good Range:** 5-20%
**Note:** High-quality measurements can override outlier detection

### Quality Score
**Definition:** Kalman-based assessment of measurement reliability
**Range:** 0.0 to 1.0 (higher = better quality)
**Threshold:** Default 0.45 for acceptance
**Components:** Kalman deviation, temporal consistency, source reliability

### Confidence Interval (CI) Improvement
**Definition:** Reduction in measurement uncertainty
**Formula:** (Raw CI Width - Filtered CI Width) / Raw CI Width × 100%
**Good Values:** >5% improvement
**Clinical Impact:** Tighter CIs = more reliable measurements

### Direction Errors
**Definition:** Cases where weight change direction is misclassified
**Example:** Raw data shows weight gain, filtered shows loss (or vice versa)
**Target:** Minimize these errors
**Clinical Risk:** Can lead to incorrect treatment decisions

### Variance Reduction
**Definition:** Decrease in measurement variability
**Formula:** (Raw Variance - Filtered Variance) / Raw Variance × 100%
**Good Values:** 10-30% reduction
**Benefit:** More consistent and predictable measurements

- **Valid Baseline:** >80% of users

### Warning Signs

#### Over-Filtering
- **Removal Rate:** >40%
- **Success Rate Drop:** >5% decrease in filtered data
- **User Loss:** >20% fewer users with valid data
- **Mean Improvement:** >2% better outcomes (too good to be true)

#### Under-Filtering
- **Removal Rate:** <5%
- **High Outlier Rate:** >25% with low removal
- **No Quality Improvement:** Minimal variance reduction
- **Impossible Changes:** >1% of measurements show impossible daily changes

#### Data Quality Issues
- **High Source Variability:** Some sources with >30% outlier rates
- **Temporal Clusters:** Outliers concentrated in specific time periods
- **Extreme Outliers:** Many measurements with >10kg deviations

## Detailed Calculation Formulas

### Success Rate Calculations

**5% Weight Loss Success Rate:**
```
users_achieving_5pct_loss = COUNT(users WHERE weight_loss_pct >= 5.0)
total_users_with_valid_data = COUNT(users WHERE raw_loss_pct IS NOT NULL)
success_rate_5pct = (users_achieving_5pct_loss / total_users_with_valid_data) × 100
```

**Weight Loss Percentage Calculation:**
```
start_weight = first_measurement_within_14_days_of_program_start
end_weight = last_measurement_before_analysis_date
weight_loss_kg = start_weight - end_weight
weight_loss_pct = (weight_loss_kg / start_weight) × 100
```

**Data Quality Impact:**
```
eligible_users = COUNT(users WHERE days_in_program >= 90)
users_with_valid_endpoint = COUNT(users WHERE raw_loss_pct IS NOT NULL)
data_completeness = (users_with_valid_endpoint / eligible_users) × 100
```

### User Inclusion Logic

**Start Weight Requirements:**
1. Look for measurement on exact start date
2. If not found, search within start_date ± 7 days to start_date + 14 days window
3. Use first measurement found in that window
4. If no measurement found, user excluded from analysis

**End Weight Requirements:**
1. Use last measurement before today's date
2. Must be after 90+ days from start date
3. If no measurements after 90 days, user excluded

**Key Code Logic (from quarterly_reporting.py:367-372):**
```python
if raw_start and raw_end and raw_start > 0:
    raw_loss_kg = raw_start - raw_end
    raw_loss_pct = (raw_loss_kg / raw_start) * 100
else:
    raw_loss_kg = None  # User excluded from analysis
    raw_loss_pct = None
```
